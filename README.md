# CHEL · объяснимый поиск автомобиля

**ЛЦТ 2026 · задача Фалькон Тех · Built with DINOv3**

[Открыть работающий прототип](http://5.144.99.200:8800/) · [Обучение](docs/TRAINING.md)

Поиск одного автомобиля на снимках разных камер: изображение и рамка автомобиля
превращаются в вектор, галерея ранжируется по cosine, а оператор получает
короткий список и проверяемый разбор выбранного кандидата.

**Статус:** рабочий CPU-прототип, интерфейс v5. Модель CHEL-KISSME1024 сохранена
из v4. Этот публичный репозиторий содержит исходный код и документацию.
Конкурсные изображения, веса, приватные разбиения и готовые test-выходы сюда
не включены. Свежий clone без весов не запускает модель; ниже перечислены
необходимые артефакты. Это не заявление о полном выполнении ТЗ: известны
пропуски номерных масок, официальный score неизвестен.

## Что умеет решение

- Принимать изображение и BBox через API или браузер.
- Строить нормированный вектор 1024 и выполнять точный cosine-поиск.
- Показывать до десяти ближайших снимков, отмечая прошедшие фиксированный порог.
- Отказываться от совпадения, если принятых кандидатов нет.
- Разлагать оценку на три точных вклада и показывать противоречия ветвей.
- Проверять влияние 16 областей двумя вмешательствами с пересчётом всей галереи.
- Сохранять разбор в JSON/Markdown с привязкой к входу, модели и галерее.
- Работать на CPU без сетевого доступа модели после подготовки окружения.

## Почему это полезно

На одной и той же **ранее исследованной локальной выборке** из 630 известных
запросов обученная метрика повысила качество отбора:

| Вариант | mAP | Верный первый результат | Верный снимок в top-10 до порога |
|---|---:|---:|---:|
| Исходный DINOv3 global, avg pooling | 10.59% | 14.60% | 24.92% |
| Прежний CHEL | 29.08% | 30.63% | 59.84% |
| KISSME global-only | 32.65% | 34.29% | 64.29% |
| **CHEL-KISSME1024** | **33.24%** | **34.44%** | **65.56%** |

Относительно прежнего CHEL в top-10 исправлены 45 запросов и потеряны 9:
413 попаданий вместо 377. Это измеренная польза для предварительного отбора.
**После порога** верный кандидат принят только в 234/630 запросов (37.14%).
В 179 случаях верный снимок остаётся доступен для ручного разбора ниже порога.
Не выдаём диагностический top-10 за точность автоматических принятий.

Дополнительный выигрыш локальных ветвей относительно global-only статистически
не установлен: +0.60 п.п. mAP, 95% CI [−0.06; +1.23]. Главный подтверждённый
прирост связан с глобальной метрикой. Независимого holdout, официального score
и замера времени операторов нет. [Полные результаты и границы](docs/RESULTS.md).

## Архитектура

```text
RGB + BBox → маски номеров → DINOv3 ViT-B/16 (заморожен, 256×256)
                           ├─ global 768 → KISSME
                           ├─ local 64
                           └─ local 192
                                 ↓ нормировка
                         вектор 1024 → cosine → top-10 / порог
                                                    ↓
                             вклады + контролируемые вмешательства

Браузер → Frontend :8080 → ML/API :8000 → DB :8002 → SQLite volume
          localhost        внутренняя Docker-сеть
```

Три сервиса запускаются независимо. Галерея сохраняется при обычном рестарте.
Для каждого её вектора проверяется fingerprint модели. Автоматического удаления
несовместимой галереи нет. Миллионный индекс, ANN и промышленная отказоустойчивость
не реализованы и не заявляются.

## Запуск

Требуются Docker с Compose, CPU и отдельно предоставленные веса. Проверенный
контейнер ML имеет лимит 6 GiB и два CPU-потока; это не измеренный минимальный
размер RAM. Для сборки образа нужна сеть; последующий запуск модели автономный.

1. Разместите файлы модели в `weights/` по [контракту артефактов](docs/REPRODUCIBILITY.md).
2. Для конкурсных примеров положите разрешённый вам `dataset.zip` в `data/`,
   а связанные с этой моделью outputs — в `outputs/`. Без них готовые примеры
   отсутствуют; собственную галерею можно наполнить через API.
3. Соберите зависимости и запустите сервисы:

```bash
mkdir -p data weights outputs
docker build -t falcon-chel:final-20260928 .
sh start_offline.sh
```

Откройте **http://127.0.0.1:8799/**; документация API — **/docs**,
спецификация — **/openapi.json**. Backend и DB не публикуют порты хоста.
Swagger assets входят в репозиторий и не требуют CDN.

Для полностью автономного переноса на другую машину заранее сохраните образ:

```bash
docker save falcon-chel:final-20260928 | gzip > falcon-runtime.tar.gz
# На целевой машине с полным набором артефактов:
sh start_offline.sh /path/to/falcon-runtime.tar.gz
```

Это исходники публичной версии; отсутствие весов нельзя исправить одним
`docker build`. Полный pipeline подготовки модели описан в
[воспроизводимости](docs/REPRODUCIBILITY.md).

## Проверки

Лёгкие проверки логики интерфейса не требуют данных, весов или GPU:

```bash
node --check explanation_ui.js
node tests/check_operator_evidence.cjs
PYTHONPATH=. python -m unittest discover -s tests -p 'test_*.py' -v
```

Для Python-тестов требуется окружение с зависимостями проекта. На опубликованном
коде прошли43 Python-теста и10 JS-сценариев; полная модель им не требуется.

В квалифицированной приватной поставке проверены реальные принятие/отказ,
кандидат ниже порога при принятом другом результате, защита от устаревшего
объяснения, сохранность галереи после рестарта, целостность выходов и CPU-инференс.
Они не подменяют проверку нового окружения после clone.

Локальная производительность на Intel i7-13700KF, два потока, 16 изображений
и два повтора: batch-1 p50 **0.383 с**, batch-8 **4.11–4.15 кадра/с**.
Веса — **366526289 байт**. Не замер оборудования жюри; время объяснения и сеть
не включены в эту цифру. [Подробности](docs/RESULTS.md).

## Ограничения

- Автоматическое маскирование номеров пропускает отдельные области. Запрет
  остаточных номерных признаков пока не подтверждён на всём наборе.
- Cosine — оценка сходства, не вероятность. Отказ не доказывает отсутствие машины.
- Карта — чувствительность модели к искусственному скрытию, не сегментация
  фар/дисков и не доказательство идентичности.
- Локальные метрики получены на уже исследованных выборках; скрытый тест неизвестен.
- Экономия времени и снижение ошибок операторов требуют отдельного пилота.
- Публичный код не содержит конкурсных данных, готовых весов и приватных manifests.
