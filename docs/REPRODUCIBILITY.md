# Воспроизводимость и контракт артефактов

Публичная версия содержит исходники. Готовые веса доступны отдельным архивом
в [Release v1.0.0](https://github.com/sweetlhare/falcon-chel-lct-2026/releases/tag/v1.0.0).
Изображения, строки dataset/split и конкурсные результаты предоставляются
правообладателем или организаторами. Без них можно запустить модель со своей
галереей, но нельзя повторить заявленные конкурсные метрики.

## Модель

Нужен каталог `weights/`:

| Файл | Назначение |
|---|---|
| `manifest.json` | Имена компонентов, их SHA256, backbone, threshold и параметры |
| `backbone.safetensors` | DINOv3 ViT-B/16 |
| `chel_v1.npz` | Первая локальная ветвь и центрирование |
| `chel_v2.npz` | Вторая локальная ветвь |
| `compression.npz` | Обученные преобразования сжатия |
| `global_metric.npz` | KISSME-преобразование global768 |
| `plate_redaction.onnx` | Детектор номерных областей |

Размер выбранных весов — 366526289 байт. Fingerprint manifest выбранного решения:
`baafd6b9cb4a431152dd6db6054ef571d313a8ee1b8310352aedc41f2ade409f`.
Хэш устанавливает соответствие конкретному эксперименту, но не заменяет
сам файл и право использования. Условия DINOv3 сохранены в `licenses/`.

## Получение замороженных весов

Архив `falcon-chel-kissme1024-weights-v1.tar.gz`, 338743901 байт.
SHA256: `ee0828478e26680b6becd8087de629cca02bd0cd2b59494aa7db05d3cb4d971d`.
Внутри только шесть компонентов модели, manifest, лицензии и provenance;
нет изображений, готовых embeddings или идентификаторов объектов.

Из корня checkout, на машине с сетью:

```bash
curl -fL -o falcon-chel-kissme1024-weights-v1.tar.gz \
  https://github.com/sweetlhare/falcon-chel-lct-2026/releases/download/v1.0.0/falcon-chel-kissme1024-weights-v1.tar.gz
printf '%s  %s\n' \
  ee0828478e26680b6becd8087de629cca02bd0cd2b59494aa7db05d3cb4d971d \
  falcon-chel-kissme1024-weights-v1.tar.gz | sha256sum -c -
tar -xzf falcon-chel-kissme1024-weights-v1.tar.gz
```

На macOS вместо `sha256sum` используйте `shasum -a 256`. Для автономной
машины доставьте уже проверенный архив и Docker-образ заранее. При загрузке
модель дополнительно проверяет SHA256 каждого компонента по manifest.
DINOv3 распространяется под собственной лицензией; см. файлы из архива.

## Инференс

После получения весов и разрешённого архива организатора:

```bash
python inference.py --archive data/dataset.zip --weights weights --output outputs/new_run
python validate_outputs.py --archive data/dataset.zip --output outputs/new_run
```

`new_run` не должен существовать. Для этих команд нужны зависимости модели;
для автономного выполнения используйте подготовленный Docker-образ.
Выпуск содержит submission.csv, candidates.csv, embeddings.npy и служебные
rows/pooling/redactions/report/model_manifest для проверки происхождения.
Порядок query/gallery определяется метаданными организатора, не именами файлов.

## Обучение

В публичном коде сохранены encoder, обучение локальных ветвей, сжатие,
метрическая голова и evaluation. Команды: [TRAINING.md](TRAINING.md).
Приватный исследовательский протокол
использовал 2500 обучающих изображений 400 ID и отдельную calibration. Seeds:
20260924 для локальных ветвей, 20260925 для сжатия, 20260928 для новых контролей.

Для точного повтора требуются **исходные фиксированные** metadata/split/masks
и encoder cache с manifests. Новое случайное разбиение не воспроизводит те же
цифры. Не объявляйте исследованные V2/V4–V7 новым независимым holdout.
На своих данных сначала зафиксируйте train/calibration/evaluation по ID
и общим кадрам, затем обучайте PCA/метрики только на train и порог на calibration.

Отдельный скрипт `train_global_metric.py` воспроизводит уже выбранную голову:

```bash
python train_global_metric.py --self-test
python train_global_metric.py \
  --training-features replay/training_features \
  --training-rows training/training_cpu_rows.jsonl \
  --center-weights weights/chel_v1.npz \
  --output replay/global_metric
```

Имена путей здесь — контракт для ваших явно подготовленных входов, не файлы,
которые уже лежат в публичном Git. Скрипт проверяет связывание ID/векторов,
размерность, конечность, train-only центр и отказ от перезаписи.
Все команды требуют реальных подготовленных артефактов. Полного приватного
training/split набора в публичном checkout нет.

## Что действительно проверено

- Глобальная голова пересчитана по сохранённым train-признакам: center/transform
  совпали побитово в проверенном offline-окружении.
- Свежий encode восьми изображений отличается от исследовательского пути
  не более 2.468e-6 по вектору.
- Полный цикл encoder→обучение всех ветвей→выходы заново не повторялся.
- Выходной валидатор проверен на целых и намеренно повреждённых данных.
- Результаты и hashes не публикуются как доказательство скрытого теста.

Разница BLAS/CPU может изменить FP32 и NPZ-байты. Сравнивайте массивы,
векторы, решения и provenance; имя каталога не является доказательством версии.
Полнота визуальных масок требует отдельного человеческого аудита: корректный
JSON/BBox и инвариантность внутри маски не доказывают, что все номера закрыты.

## Точный формат manifest

`inference.Model` читает следующие поля. Ниже **синтетическая схема**: нулевой
порог, размер и строки `REPLACE_*` не являются параметрами или хэшами реальной
модели. Этот пример нельзя использовать для запуска.

```json
{
  "name": "CHEL-KISSME1024",
  "backbone": "vit_base_patch16_dinov3.lvd1689m",
  "threshold": 0.0,
  "total_bytes": 0,
  "global_metric": "global_metric.npz",
  "sha256": {
    "backbone.safetensors": "REPLACE_WITH_ACTUAL_SHA256",
    "chel_v1.npz": "REPLACE_WITH_ACTUAL_SHA256",
    "chel_v2.npz": "REPLACE_WITH_ACTUAL_SHA256",
    "compression.npz": "REPLACE_WITH_ACTUAL_SHA256",
    "global_metric.npz": "REPLACE_WITH_ACTUAL_SHA256",
    "plate_redaction.onnx": "REPLACE_WITH_ACTUAL_SHA256"
  }
}
```

Для реального manifest вычислите SHA256 по байтам всех шести файлов и их
суммарный размер. `threshold` — число, выбранное на calibration для **итогового**
вектора с KISSME; порог из старого `compression/selection.json` ему автоматически
не соответствует. Для замороженных поставленных весов используйте их оригинальный
manifest целиком. Путь `global_metric` обязан также присутствовать в `sha256`.
Детектор — отдельная pretrained-модель; обучающие команды локальных ветвей его
не создают. Точные готовые веса и фиксированные приватные splits необходимо
получить отдельно от авторов/организаторов, публичной ссылки на них в Git нет.

## Проверка без конкурсных данных

После загрузки весов, в окружении проекта:

```bash
python tests/qualify_empty.py --weights weights --report /tmp/falcon-own-gallery-check.json
```

Нужен новый путь отчёта вне `weights/`. Два синтетических снимка создаются
с seed 20260928. Проверяются encode, пустой поиск, добавление своей галереи,
поиск того же снимка, объяснение с токеном, три ошибочных состояния и
сохранение данных после перезапуска API. API и DB временные и слушают только
localhost; действующий прототип не используется. Все свои процессы завершаются,
временная галерея удаляется. Не запускайте проверку с `python -O`.

Это проверка работоспособности и изоляции, не качества ReID или масок номеров.
Для настоящей parity на изображениях организатора нужна следующая проверка.

## Проверка checkout на предоставленной модели

Следующая команда не меняет веса, outputs или существующие сервисы. Она выбирает
первые четыре query и четыре gallery изображения, применяет сохранённые маски,
строит свежие векторы и сравнивает их с outputs. Затем поднимает только временную
SQLite и API на свободных loopback-портах, проверяет свежий поиск и неверный токен
и завершает свои процессы. Нужны реальные артефакты и зависимости проекта:

```bash
PYTHONPATH=. python tests/qualify_runtime.py --self-test
PYTHONPATH=. python tests/qualify_runtime.py \
  --weights weights --archive data/dataset.zip --outputs outputs/new_run \
  --report qualification.json --source-revision "$(git rev-parse HEAD)"
```

Report должен быть новым файлом вне каталогов weights/outputs. Поля source hashes
связывают проверку с фактическим кодом; revision, переданный пользователем,
служит дополнительной меткой, а не заменой хэшей. Пять испорченных синтетических
контроля обязаны отвергаться. Если предоставленный набор не содержит принятых
или отказанных примеров, отчёт явно покажет неполное покрытие этих сценариев.
Успешная проверка подтверждает ограниченную численную совместимость и API,
не полный training replay, качество на скрытом тесте или полноту маскирования.
